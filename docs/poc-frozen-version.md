# Зафиксированная версия PoC для замера

Дата фиксации: 25.11.2026. Git-тег: `poc-v2` (заменяет `poc-v1`).

Отличие v2 от v1 — только интерфейс: источники выводов в сводке стали кликабельными (2.5.2 — «ссылка из сводки открывает письмо»). Промпт, модель, инструменты и проверки не менялись, поэтому результаты прогонов v1 ниже относятся и к v2.

После фиксации код, промпт и настройки не меняются до конца замера. Если что-то пришлось изменить, это новая версия (`poc-v3`), и результаты двух версий не смешиваются.

| Параметр | Значение |
|---|---|
| Версия PoC (хэш в журнале, `poc_version`) | `2bad3ff627f8` |

## Проверка перед фиксацией

4 прогона по 32 кейса (`with_mail_search`), 128 эпизодов, сверка `python -m poc eval` с `expected.json`:

| Поле | Совпало с эталоном |
|---|---|
| Сбои и таймауты | 0 из 128 |
| Предлагаемый переход | 128/128 |
| Нужные письма | 127/128 |
| Подтверждённый этап | 126/128 |
| Пометка «Требуется проверка» | 124/128 |
| Задержка модели | средняя 25 с, максимум 37 с |

Нестабильные кейсы: TEST-01 (лишняя пометка, 3 из 4), TEST-12 (этап при противоречии с CRM, 2 из 4), TEST-13 (письма, 1 из 4), TEST-23 (пометка, 1 из 4).

Оговорка: закрытый набор (`holdout`) использовался при доработке (разбор ошибок TEST-15, TEST-31 и др.), поэтому эти цифры — не независимая оценка. Сверка `eval` проверяет только формальные поля; содержательную оценку по протоколу 2.4 выполняет оценщик.

## Перед замером

1. Переименовать или удалить `poc_data/poc.sqlite`, чтобы в журнале остались только строки замера.
2. Положить `TEST/assignments.csv` (`participant,order_no,case_id,mode`).
3. Запуск: `.venv/bin/streamlit run poc/app.py --server.address 127.0.0.1 --server.headless true --browser.gatherUsageStats false`.
4. Проверить в журнале, что у строк замера `poc_version = 67423c911ea1`.
